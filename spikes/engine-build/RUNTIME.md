## Helper packaging repair and failure limits

Exact Chromium [child-process path selection](https://chromium.googlesource.com/chromium/src/+/refs/tags/156.0.8078.48/content/browser/child_process_host_impl.cc) requests `(Aperitif)`, `(Aperitif Renderer)` and `(Aperitif GPU)` when `AperitifHelpers` is enabled. The feature is disabled in its declaration, but the pinned macOS [developer field-trial configuration](https://chromium.googlesource.com/chromium/src/+/refs/tags/156.0.8078.48/testing/variations/fieldtrial_testing_config.json) enables it. Unbranded developer builds use that configuration by default; CEF disables it automatically only for official builds. The resulting developer-runtime expectation therefore differed from the four names CEF bundled.

[`helper-packaging.patch`](helper-packaging.patch) extends the exact CEF `cef_app` helper list with `content_mac_aperitif_helpers`. Its separate [`helper-packaging.json`](helper-packaging.json) locks original/patched `BUILD.gn` bytes and patch bytes; the original checkout lock and digest remain unchanged. The guarded patch stage applies it only to embedded CEF, refuses unexpected edits, and treats an identical applied patch as success. Build and runtime checks require its exact applied hash. GN regeneration during the incremental `cefsimple` build creates and packages the three additional helpers; no binaries are copied or renamed manually.

This follows the helper-list/unchanged-entrypoint approach in pinned [Content Shell](https://chromium.googlesource.com/chromium/src/+/refs/tags/156.0.8078.48/content/shell/BUILD.gn). CEF's existing helper still calls `CefScopedSandboxContext::Initialize` before loading the framework. It changes no sandbox flags, feature configuration, DCHECK or runtime security policy. It is packaging/name compatibility, **not** adoption or proof of Chrome's newer pure-C Apéritif preinitializer architecture. CEF's explicit Alerts-path override continues to select its existing `(Alerts)` helper, so `(Aperitif Alerts)` is not added by this bounded repair.

The missing helper is a concrete launch failure. The fatal stack independently reports GPU-cache backend cleanup doing blocking file closure on the UI thread after GPU launch failure; repair the helper first and retain that failure if it recurs. The earlier code-sign clone cross-volume error is explicitly nonfatal in the pinned source and intentionally ignores the usual temporary-directory override. Duplicate Objective-C class warnings were also observed; this evidence does not establish them as the abort's cause. Do not suppress DCHECKs, disable sandboxing or change security policy to obtain a runtime pass.

## First runtime acceptance

1. Run the control case without native surfaces or extensions. Verify page rendering, visible ordinary toolbar/origin UI, and clean close/process exit.
2. Run the reservation case with its separate fresh mock Profile. At a large normal window, verify the expected260px left/44px top space and unclipped toolbar/page. Compare actual rectangles; an empty gap alone is insufficient.
3. Resize, maximize and test minimum sizes. Exact source can fall back to full host bounds when insetting produces an empty rectangle. Record that case rather than claiming universal reservation.
4. Enter/exit fullscreen. Reservation is intentionally disabled there; confirm stock geometry and restoration on return.
5. Only after basic geometry passes, exercise the native split, divider, focus indication and popup/permission anchors. Real extension checks and app-owned Swift input/accessibility remain later gates.
6. Record failures separately from later successes. Verify completed shutdown and absence of the owned process; a close request alone is not completion.

Tests use synthetic temporary trees and mocked Mach-O metadata. Guard tests exercise exact helper patch application, idempotence and hash/edit refusal; runtime tests reject a missing Apéritif variant. They check refusal of active/failed/wrong-stage builds, GN comments/duplicate settings, dependency resolution/escape, architecture, fresh Profile policy, fixed flags and absence of launch/write effects. They do not compile or run Chromium.
