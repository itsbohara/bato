# Close browsers and request application quit

Date: 2026-10-27. Source review uses the exact pinned CEF revision and Chromium156.0.8078.48. Runtime success for one action does not establish success for the other.

The native **Close all browsers** button calls the sample's `SimpleHandler::CloseAllBrowsers(false)`. It requests closure of the browsers tracked by that handler, allowing normal unload handling. The final sample `OnBeforeClose` calls `CefQuitMessageLoop`. In the exact [CEF main runner](https://github.com/chromiumembedded/cef/blob/4fa4ab516dacf6c49fc7e6e70d2b7ebce29fa35f/libcef/browser/main_runner.cc), this releases CEF's application-controller keepalive, while actual loop termination still depends on Chrome's remaining keepalive state. Therefore zero Swift bridge references does not itself prove the application quit.

The separate **Quit application** button dynamically resolves `IDC_EXIT`, checks `CanExecuteChromeCommand` and dispatches it through the supported CEF browser-host API. The exact [CEF implementation](https://github.com/chromiumembedded/cef/blob/4fa4ab516dacf6c49fc7e6e70d2b7ebce29fa35f/libcef/browser/chrome/chrome_browser_host_impl.cc) delegates to Chrome's command controller. There is no direct call to private Chromium symbols, forced close or process-exit fallback. A live Chrome-style browser is required to dispatch this command; the panel cannot invoke it after its final browser has detached.

The pinned [command controller](https://github.com/chromium/chromium/blob/156.0.8078.48/chrome/browser/ui/browser_command_controller.cc) routes `IDC_EXIT` to [Exit](https://github.com/chromium/chromium/blob/156.0.8078.48/chrome/browser/ui/browser_commands.cc), which calls `AttemptUserExit`. The exact [application lifetime implementation](https://github.com/chromium/chromium/blob/156.0.8078.48/chrome/browser/lifetime/application_lifetime.cc) sends a global closing-all-browsers notification before invoking the platform exit path. That is an additional step compared with directly looping over the sample's browsers.

The macOS nuance matters: the pinned [platform implementation](https://github.com/chromium/chromium/blob/156.0.8078.48/chrome/browser/browser_process_platform_part_mac.mm) eventually calls `NSApp terminate:`. The [upstream cefsimple subclass](https://github.com/chromiumembedded/cef/blob/4fa4ab516dacf6c49fc7e6e70d2b7ebce29fa35f/tests/cefsimple/cefsimple_mac.mm) casts `NSApp.delegate` to its sample delegate and sends that delegate's termination selector. The first actual native Quit test exposed an ownership mismatch: native Chrome had replaced that delegate with `AppController`, which did not implement the sample selector, producing an Objective-C unrecognized-selector exception.

The bounded sample override now routes `SimpleApplication.terminate:` directly through the known `SimpleHandler::CloseAllBrowsers(false)` path rather than messaging an unchecked delegate type. It retains the original sample's closing guard. The handler marshals to the CEF UI thread when needed. There is no call to `super terminate:` or forced process termination. This also affects standard termination requests reaching this subclass; it does not replace Chrome's delegate or patch engine internals. The global closing notification preceding the `IDC_EXIT` path remains intact. This corrects the demonstrated sample dispatch mismatch but is not a proven cure for the earlier intermittent extension-run hang.

Diagnostics distinguish command availability, dispatch, sample browser-list counts, the request/return of `CefQuitMessageLoop`, actual message-loop return and completed CEF shutdown. Command dispatch alone is not quit completion. The coordinator must test the native button with the synthetic controller extension and confirm process exit. Any failed or cancelled run remains evidence; successful follow-ups do not erase it.

## Revised sample runtime, 2026-10-29

After manual unlock, the coordinator used the unchanged dedicated mock-Keychain Profile and controller extension, restored the saved pair, observed both controlled pages, separated/re-paired it, closed its test tabs and clicked the actual native **Quit application** control. The previous selector exception did not recur. Logs recorded `sample-terminate-requested`, completed command dispatch, both remaining CEF browsers closing, native detach and the request/return of `CefQuitMessageLoop`.

The process nevertheless remained alive without message-loop exit or completed CEF shutdown. A new-tab window was observed afterward, with an incorrect-profile-type new-tab diagnostic. Its triggering event is unestablished. After closing that window did not finish termination, the coordinator captured an owned-process sample outside Git and stopped only that disposable process with bounded SIGTERM. This is a failed graceful-quit test; removing the exception did not complete the fix. See the follow-up in [sanitized evidence](quit-runtime-evidence.json).

Pinned source identifies a missing lifecycle step: macOS [`AttemptExitInternal`](https://github.com/chromium/chromium/blob/156.0.8078.48/chrome/browser/lifetime/application_lifetime.cc) deliberately leaves the trying-to-quit state to the application controller. Normal [`BrowserCrApplication::terminate:`](https://github.com/chromium/chromium/blob/156.0.8078.48/chrome/browser/chrome_browser_application_mac.mm) enters `AppController::tryToTerminateApplication`. That controller performs quit confirmation, download/active-app checks and calls `CloseAllBrowsersAndQuit`; it also owns a separate keepalive released by `allowApplicationToTerminate`. CEF's [`HandleMainMessageLoopQuit`](https://github.com/chromiumembedded/cef/blob/4fa4ab516dacf6c49fc7e6e70d2b7ebce29fa35f/libcef/browser/main_runner.cc) releases its own keepalive, not the controller's. The sample's direct-handler override bypasses Chrome's normal application-quit entry. This source gap explains why zero tracked CEF browsers is insufficient; the exact remaining runtime keepalive was not instrumented.

A next experiment needs a framework-owned, opt-in quit-request entry preserving Chrome's normal confirmation, download checks, active-app vetoes, unload cancellation and termination notifications. The client should call a supported CEF boundary, not Chromium private selectors or symbols. Calling `CloseAllBrowsersAndQuit` directly would skip controller preparation; `AttemptUserExit` alone returns through the same overridden `NSApp terminate:`. Chromium explicitly does not support the standard `applicationShouldTerminate:` route. No forced-exit fallback or direct superclass termination is acceptable evidence. Cancellation must leave the browser usable, and approval must actually complete the loop, shutdown and process exit.
