# Packaging plan (milestone 5)

Goal: a locally signed `Bato.app` that the user can run from the SSD like any Mac app. Distribution beyond this Mac (Developer ID signing, notarization, updates) stays out of scope, per DESIGN.md "First-alpha distribution".

## Decisions

1. **Identity.** App and menu name `Bato`; bundle id `com.itsbohara.bato` (no id is specified in the repo docs); helpers `com.itsbohara.bato.helper[.alerts|.renderer]`, executables renamed together because CEF finds helpers as `<main executable> Helper (<kind>)`. Version from one file, `VERSION` at the repo root (`CFBundleShortVersionString`); `CFBundleVersion` is `git rev-list --count HEAD`.
2. **Where identity is applied.** `spikes/engine-build/package_app.py` rewrites a copy of `out/Debug_GN_arm64/cefsimple.app`; the engine build output and the GN targets keep the `cefsimple` names, so no engine rebuild is needed for identity. Menu titles come from Chromium's product string, so the client renames them at runtime (`MenuBranding` in `WorkspaceSlot.swift`).
3. **State paths do not change.** The engine guard still refuses any cache path outside `SSD/runtime/profiles/` and still requires `--use-mock-keychain`. The alpha state is therefore `SSD/runtime/alpha-state` (organization) and `SSD/runtime/profiles/alpha-v1` (engine Profile). Moving to `~/Library/Application Support/Bato` needs a deliberate guard change plus the production Keychain decision (TASK.md) and is a later milestone; nothing migrates now.
4. **Launching without flags.** The packaged app carries the launch switches in its Info.plist (`BatoDefaultArguments`); `main()` applies them only when the command line names neither `--bato-workspace-state` nor `--cache-path`, so test launches are never redirected.
5. **Promos.** Narrowest point is the existing workspace-mode switch rewrite in `cefsimple_mac.mm`: `--no-default-browser-check` plus a `--disable-features` list of the enabled-by-default desktop `IPH_*` features (including `IPH_HighEfficiencyMode`, the "Make Chromium faster" bubble).
6. **Icon.** Original placeholder generated by `packaging/make_icon.swift` (rounded tile, rounded "B"), built with `iconutil`. A file at `spikes/engine-build/packaging/Bato.icns`, or `--icon`, replaces it.
7. **Signing.** Ad-hoc, inside-out: loose Mach-O files, nested bundles deepest first, the app last. Verified with `codesign --verify --deep --strict` and `spctl -a -vv` (expected rejected).
8. **Component build.** The Debug engine is a component build: the executables resolve about 500 dylibs through `@rpath`, which reaches the build directory only. The packager clones the dependency closure (`runtime.dependency_closure`) into `Contents/Frameworks` (APFS clone, no extra space).

## Verification

Follow RESUME.md: stage mirrors, regenerate client patch, `native_slot.py check`, `app/tools/dev.py test` (log `logs/pkg-swift-tests.log`), `build --execute` (segment `logs/pkg-build-segment.log`), then real-host runs with fresh wrappers `tmp/launch-pkg-v1.py`.. (mock keychain, fresh state copy, receipt guard), quit through the app menu, and a LaunchServices cold launch with a web link.
