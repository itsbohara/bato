# Browser chrome, site icons and folders

Date: 2026-11-01. Status: source verification, bounded real-host checks and same-provider persistence restart passed.

The opted-in attached normal workspace window now suppresses Chromium's horizontal tab strip. Swift's sidebar remains the page list. Chromium retains its toolbar, address/origin UI, extension anchors and the native forty-four-point window-control strip. Fullscreen and unowned windows retain stock behavior. This is a bounded step toward Arc-style chrome, not complete replacement of browser security or extension controls. Existing slot, sheet, fullscreen and teardown guards remain intact; the engine ABI remains nine authored exports and ten WorkspaceConfigure arguments.

Site icons use CEF's advertised favicon URLs and cookie-free `DownloadImage` path, rather than a Swift fetch or third-party icon service. Only supported HTTP(S) destinations are requested. CEF requests a maximum thirty-two-DIP image; returned PNGs are checked to be no larger than 128×128 pixels and 256 KiB before crossing the bridge. Token, browser identity, icon revision and exact live-page generation reject stale results after navigation, replacement, closure or detach. Icons remain session-local presentation data, with existing symbols as fallbacks. Matching terminal page events clear cached icons so an unloaded saved entry does not retain the icon of a different last-live destination. No browsing-derived icon URLs, image data or browser profiles are committed; the repository contains only the authored synthetic fixture icon.

Workspace folders are a flat ordered list of metadata references to the existing saved-pin entries. Complete pins stay in `Workspace.pins`; folder membership cannot duplicate a pin or point to another workspace's entries. Missing folder fields decode as an empty list, and encoding omits empty folder lists to retain legacy document shape. Folder IDs join global identity validation. Names trim on edits and must contain 1–80 characters without control characters. Invalid names, duplicate references and dangling or foreign references reject the transaction.

The native sidebar displays unfiled pins, then ordered folder headers and their expanded pin rows. Workspace actions offer New Folder; folder actions offer rename, ordering and Dissolve Folder, which preserves every pin. Pin menus move into a folder or remove membership. Disclosure persists collapsed state without unloading the page. Pin ordering stays within its folder or unfiled group. Unpin, Favorite conversion and workspace transfer clean source references atomically. Metadata changes preserve page identity, URLs, selection, live generations and engine visibility; pending closes block membership changes and container dissolution. Folder editor cancellation is a local draft. Menus capture workspace/folder identities, and rerendering restores focused folder controls by stable ID and role.

## Current limits

Folders are flat; nesting and drag-and-drop hierarchy are not implemented. Icons require a loaded page and are not persisted or prefetched for unloaded entries. The Chrome toolbar and origin/extension controls remain visible; the complete Arc-style browser chrome is unfinished. Actual window dragging, traffic-light button clicks, short-height layout, light appearance, broad accessibility navigation, rapid fullscreen transitions and extension behavior require their own acceptance. Folder reordering and removing a pin from a folder have model/runtime tests and source review but no real-host interaction acceptance. Stable focus for every folder control was source-reviewed and package-built, not broadly runtime-accepted. Only the recorded steady-fullscreen roundtrip is accepted here. The previous command-bar rendering anomaly remains recorded in COMMAND-BAR-RESULTS.md; this work does not claim to fix its cause. No daily-use or production readiness follows.
