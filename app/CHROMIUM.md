# Native Chromium workspace experiment

This opt-in source-built host connects `BatoBrowserUI`, `BatoRuntime`, the organization store and normal Chromium tabs in one window. Bounded runtime acceptance now covers real creation, saved navigation/reset, default-dialog cancellation, workspace switching and same-provider clean restart. It is a developer experiment, not a distributable or daily-use browser.

Use the existing pinned SSD engine checkout and `spikes/engine-build/native_slot.py`; do not rerun checkout/configure. The client overlay stages four Swift modules into `cef/tests/cefsimple/bato/` and links their objects into the existing native-slot library. Nine source mirrors are checked against repository bytes before building, so a stale staged sidebar or runtime is refused.

Workspace mode requires `--bato-workspace-state=/absolute/organization/directory` and initial `--url=about:blank`, in addition to the existing native-slot/reservation/Quit flags. The first slice supports one window and one explicitly bound engine request context. The organization Profile UUID is checked against that binding; it does not establish additional Profile isolation.

Dedicated synthetic acceptance Profiles use mock Keychain on every launch, including restarts. Keep those Profiles separate from personal/baseline data. The initial blank page is a retained placeholder, protected against website navigation. Selecting an empty workspace uses it; closing it through Chrome's tab strip creates a replacement only when needed and never during window/application teardown.

Native address entry creates same-window tabs using an authored helper that returns the exact inserted WebContents' CEF identity. Each live Swift generation binds to a fixed retained browser ID. Main-frame URL/title events update organization through validated commits. Native sidebar and exposed Chrome tab-strip selection synchronize. CmdT native focus and CmdW from native/page focus passed in bounded synthetic checks. A public AppKit local event monitor handles only exact CmdT/W in the active owned key window, checks sheet/modal/managed-page state and is removed on detach. Sidebar key equivalents are disabled in this host so they cannot target a remembered background entry. Chromium menu targets/actions remain intact; untracked tab close passes through. Queued CEF commands revalidate active identity. File-menu New Tab remains Chrome-owned; its organization integration is pending. Default Chromium beforeunload remains in charge of cancellation, observed through a WebContents-owned close observer.

Explicit sidebar/CmdW closure changes organization only after confirmed engine close. Unsolicited Chrome tab-X/window/application teardown unloads the handle while preserving its organization entry. Thus native tab-X currently differs from a Bato temporary-tab close. Untracked Chrome-created tabs, additional windows, fullscreen commands, split ownership and remaining extension checks are not complete application behavior.

The standalone `BatoShell` remains an organization preview. Its package declares macOS15 as a build floor; the source experiment's Swift action targets the existing CEF macOS13 ABI to match its executable. Compilation and acceptance on this Mac do not establish support for either minimum OS version.

## Explicit saved destination updates

Pins and Favorites expose Update Saved URL in their context menu after a loaded page navigates to a different address. Ordinary navigation still changes only the session URL. The explicit action replaces the saved destination with the latest committed HTTP(S) address, preserving the entry UUID, placement, selection and live page. Unloading and reopening then uses that saved destination.

The action is disabled for unloaded, unchanged, closing or unavailable pages. Runtime rechecks eligibility when invoked and refuses updates after unsupported navigation or a failed navigation save, until a valid destination commits. Per-generation navigation-attempt tokens prevent an older callback from clearing a newer rejection during observer reentrancy. This transient guard stays out of organization storage. No engine API or organization schema changed. Saved status can be removed through the context actions described below.

Fifty-four Swift tests pass (16core,9store,3session,26runtime), including eight new cases for saved-only edits, shared Favorites, rejected contexts, persistence failures, stale generations, reentrant navigation, and unload/reopen behavior. ## Unpin and remove from Favorites

Unpin moves a pin to the end of the current workspace’s temporary tabs. Remove from Favorites does the same for a shared Favorite and removes it from Profile-wide Favorites. Both retain the entry UUID, title, latest session URL, loaded page and current selection. A background action leaves the selected page unchanged. Other workspaces that selected the removed Favorite have only that obsolete selection cleared; unrelated entries/selections remain intact.

Conversion is an atomic organization transaction, including clearing savedURL. It does not navigate, load or close a page. Unloaded saved entries can be converted without opening them. A pending close blocks conversion until confirmation or cancellation, preserving the close request’s saved/temporary meaning. Once converted, ordinary temporary-tab closure waits for the engine’s confirmation and removes the entry; Cancel keeps it. The temporary tab can be pinned or added to Favorites again through the existing menu.

Sixty-two Swift tests pass (19core,9store,3session,31runtime), with eight added cases for identity/order/selection, shared Favorite ownership, unloaded/background conversion, save failure, pending close, confirmed/cancelled closure and late callbacks. Actual source-host checks passed live Unpin, same-ID Favorite promotion/removal from another workspace without selecting or recreating its page, converted-tab restoration across same-provider restart, and pinning it again. ## Sidebar ordering

Move Up and Move Down are available in every sidebar entry’s context menu. They move an entry by one place within its existing Favorites, Pinned or Tabs section. Favorites order is shared by workspaces using the same Profile. Entries keep their full contents, identity and selection; order changes do not create, focus, navigate or close engine pages. Unloaded pages stay unloaded, and pending close requests retain their meaning.

Boundary actions are disabled. Runtime rechecks the current section/order when the action is invoked, so a stale menu cannot move an entry into a different section. Saves commit before publication and a failed save preserves the prior order. Existing array storage represents the ordering, so no schema or engine API change is needed.

## Workspace ordering

The Workspace actions menu beside Edit… offers Move Workspace Up and Move Workspace Down. These adjacent moves change the global workspace picker order while retaining workspace UUIDs, Profile associations, all entries and selections. The current workspace and visible page stay active. Boundary commands are disabled, and invocation rechecks the captured workspace UUID against current organization.

Order saves transactionally before publication, without creating, selecting, navigating or closing pages. Pending closes and unloaded pages retain their state. A failed save leaves the previous order intact. The existing workspace array persists order; no schema or engine API change is required. This control is in the Chromium-connected sidebar; the standalone preview UI is unchanged. See `spikes/engine-native-slot/workspace-order-evidence.json` for verification and limits.


## Move pages between workspaces

Pin and temporary-tab menus now offer Move to Workspace, listing other workspaces that share the current Profile in saved order. Moving appends the same full entry to the destination’s matching section, preserving UUID, kind, saved destination and latest session URL. Favorites stay Profile-wide and have no transfer action. Cross-Profile transfers and moves while that entry is closing are rejected.

The current workspace stays active and the destination’s selection remains unchanged. Moving the selected entry clears only its source selection; after the save commits, the engine hides the moved page while retaining its live generation. Moving a background entry has no engine effects. Unloaded entries remain unloaded, and a failed save preserves organization and page visibility. No schema or engine API changes; the standalone preview UI is unchanged.
